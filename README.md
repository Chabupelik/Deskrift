# 🖥️ Deskrift — Self-Hosted Web-Based Remote Desktop

**Deskrift** — это клиент-серверная платформа для удаленного управления рабочим столом Windows через веб-браузер. Проект использует концепцию аппаратного видеостриминга: экран кодируется силами видеокарты (**NVIDIA NVENC H.264**), передается по WebSockets и аппаратно декодируется прямо в браузере через **WebCodecs API** с задержкой **< 50 мс** при **60 FPS**.

Авторизация в веб-интерфейсе реализована без постоянных паролей — через персонального **Telegram-бота** с подтверждением входа в один клик.

---

## 🎯 1. Концепция и архитектурный подход

В веб-ориентированном удаленном доступе исторически сложилось два подхода:

1. **Тайловый подход (RFB / VNC / RDP):**
   * Передает изменения экрана отдельными прямоугольными областями (*dirty rectangles*).
   * **Назначение:** Оптимально для статичного интерфейса, офисных документов и администрирования серверов при минимальном трафике.
   * **Ограничение:** При проигрывании видео, анимаций или запуске динамичных приложений программный опрос экрана и сжатие тайлов создают высокую нагрузку на CPU хоста и задержки от 300 до 1000+ мс.

2. **Подход видеостриминга (Deskrift):**
   * Экран захватывается целиком из видеопамяти и непрерывно кодируется аппаратным чипом видеокарты в единый видеопоток H.264 (архитектура, аналогичная Moonlight / Sunshine).
   * **Назначение:** Высокая плавность (60 FPS), ультранизкая задержка и нулевая нагрузка на центральный процессор хоста.
   * **Клиент:** В отличие от нативных приложений (Parsec, RustDesk), Deskrift выводит картинку в стандартный браузер через современный стандарт **WebCodecs**, не требуя установки клиентских программ или расширений.

## 🏗 2. Архитектура системы

Система состоит из трех независимых компонентов: **Desktop Agent** (ПК под управлением Windows), **Relay Server & Bot** (Linux VPS) и **Web Client** (веб-приложение в браузере).

## ⚡ 3. Видеопайплайн

1. **Режим ожидания (Standby Mode):**
   * Пока браузерный клиент не подключен, агент на ПК находится в фоновом режиме ожидания.
   * Процессы захвата и кодирования не работают: нагрузка на процессор и видеокарту составляет **0%**.
   * При открытии веб-сессии сервер отправляет управляющий сигнал `start_stream`, и агент запускает энкодер. При закрытии вкладки стриминг мгновенно останавливается сигналом `stop_stream`.

2. **Захват экрана (Screen Capture):**
   * **Основной метод:** Desktop Duplication API (DXGI / D3D11) — захват кадра напрямую из видеопамяти GPU.
   * **Резервный метод (Fallback):** GDI BitBlt — автоматическое переключение, если интерфейс дупликации экрана занят другой программой или недоступен.

3. **Кодирование (NVIDIA NVENC):**
   * Параметры энкодера: `-preset p1 -tune ull -zerolatency 1 -delay 0 -profile:v baseline -bf 0 -b_ref_mode 0`.
   * Полное отключение B-кадров и буфера переупорядочивания (DPB = 0) гарантирует отправку каждого кадра без задержки на накопление пакетов.
   * Аппаратный алгоритм **Spatial Adaptive Quantization** (`-spatial-aq 1 -aq-strength 8`) сохраняет резкость шрифтов, линий редакторов кода и мелких деталей интерфейса.

4. **Парсинг битового потока (Bitstream Slicing):**
   * Внутренний парсер агента читает байтовый поток из FFmpeg и разделяет его по маркерам Access Unit Delimiter (`0x0000000109`).
   * Каждый кадр помечается 1-байтовым префиксом (`0x01` — ключевой IDR кадр, `0x00` — дельта-кадр) и отправляется в WebSocket как законченный фрейм.

5. **Воспроизведение в браузере (WebCodecs):**
   * Браузер принимает кадр, передает его аппаратному декодеру `VideoDecoder` и моментально отрисовывает на `<canvas>` через `ctx.drawImage`.
   * Декодер инициализируется в профиле Constrained Baseline, что исключает внутреннюю буферизацию кадров движком браузера.

## 🎮 4. Подсистема ввода (Input Subsystem)

* **Мышь:** Координаты нормализуются под базовую сетку `1920×1080`. Для устранения избыточных сетевых сообщений отправка событий `mousemove` синхронизирована с `requestAnimationFrame` и фильтрует дублирующиеся позиции.
* **Клавиатура:** Поддерживаются системные комбинации клавиш. Для корректной работы в играх и 3D-приложениях виртуальные коды клавиш транслируются в аппаратные скан-коды через `MapVirtualKeyW` с выставлением флагов расширенных клавиш `KEYEVENTF_EXTENDEDKEY`.
* **Буфер обмена:** Поддерживается передача текста из клиентского буфера напрямую в удаленный буфер обмена Windows (`OpenClipboard` / `SetClipboardData`).

## 🛡 5. Безопасность и 2FA

1. **Вход через Telegram (Push 2FA):**
   * При открытии веб-клиента генерируется временный токен авторизации (TTL 3 минуты).
   * Бот присылает владельцу сообщение с IP-адресом, временем и клиентом браузера и двумя Inline-кнопками: `[ Разрешить доступ ]` и `[ Заблокировать ]`.
   * После подтверждения токен активируется в Redis, и браузер автоматически переходит в режим трансляции.
2. **Rate Limiting:**
   * Защита от спама запросов на авторизацию через Redis (не более 5 попыток за 15 минут). При успешном входе лимит сбрасывается.
3. **Авторизация агента:**
   * Десктоп-агент соединяется с сервером по постоянному криптографическому токену `PC_SECRET`.

## 💻 6. Стек технологий

| Компонент | Технологии |
|---|---|
| **Desktop Agent** | Go 1.22+, Win32 API (`user32.dll`, `kernel32.dll`), `gonutz/wui/v2` (нативный GUI настроек), `energye/systray` (системный трей), gorilla/websocket |
| **Медиа-движок** | FFmpeg 6+, NVIDIA NVENC (аппаратное H.264 кодирование), DXGI Desktop Duplication API (`ddagrab`), GDI Grab |
| **Web Frontend** | Vue 3, TypeScript, Vite, Pinia, WebCodecs API (`VideoDecoder`), HTML5 Canvas |
| **Relay Backend** | Python 3.12, FastAPI, Uvicorn, Asyncio WebSockets, Pydantic v2 |
| **Хранилище / Кэш** | Redis 7 (состояние сессий, лимиты, pub/sub) |
| **Telegram Bot** | Python, aiogram 3.x |
| **Инфраструктура** | Docker, Docker Compose, Nginx |

## ⚙️ 7. Сборка и запуск

### Шаг 1. Серверная часть (VPS)

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/Chabupelik/Deskrift.git
   cd Deskrift
   ```

2. Создайте файл конфигурации `.env`:
   ```bash
   cp .env.example .env
   ```

   Заполните основные параметры:
   ```env
   # Секретный токен для подключения ПК
   PC_SECRET=your_generated_random_secret_token

   # Telegram-бот для подтверждения входа
   TELEGRAM_BOT_TOKEN=123456789:ABCDEF...
   TELEGRAM_OWNER_ID=123456789

   # Redis
   REDIS_URL=redis://redis:6379/0

   # Разрешенные домены для CORS
   ALLOWED_ORIGINS=https://desk.yourdomain.com
   ```

3. Запустите контейнеры:
   ```bash
   docker compose up -d --build
   ```

---

### Шаг 2. Агент на ПК (Windows)

#### Требования:
* Windows 10 или 11 (x64)
* Видеокарта NVIDIA (GeForce GTX 10xx / RTX 20xx / 30xx / 40xx или новее)
* Установленный и доступный в `PATH` бинарник **`ffmpeg.exe`** с поддержкой `h264_nvenc`

#### Сборка бинарника:
```bash
cd desktop
go build -ldflags="-H=windowsgui -s -w" -o deskrift.exe ./cmd/deskrift
```

#### Запуск и настройка:
1. Запустите `deskrift.exe` (приложение работает в фоновом режиме и сворачивается в трей возле системных часов).
2. Нажмите правой кнопкой мыши по иконке в трее и откройте **«Настройки»**:
   * **Адрес сервера:** `wss://desk.yourdomain.com`
   * **Секретный ключ ПК:** значение `PC_SECRET`, заданное в `.env` сервера.
   * **Качество видео:** Высокое (60 FPS, 10 Mbps) / Среднее (30 FPS, 5 Mbps) / Низкое (720p 24 FPS, 2 Mbps).
   * **Автозапуск:** отметьте чекбокс для автоматического старта приложения при входе в Windows.
3. Нажмите **«Сохранить»**. Настройки сохраняются локально в `%APPDATA%\Deskrift\config.json`. Агент перейдет в статус `В сети (ожидание)`.
